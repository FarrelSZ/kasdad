### Slide 14 – Data Format

Slide ini memperkenalkan empat format berkas yang umum untuk menyimpan dan bertukar data, yaitu CSV, TSV, XML, dan JSON, masing-masing dengan contoh isi berkasnya.

**Analogi.** Empat cara menulis daftar belanja. CSV: satu baris per barang, bagian-bagiannya dipisah koma. TSV: sama, tetapi dipisah tab. XML: tiap barang dibungkus label pembuka dan penutup, seperti kotak bersekat. JSON: tiap barang ditulis sebagai pasangan “nama: isi”, dan isinya boleh berupa daftar lagi.

**Isi slide**

Empat butir, masing-masing dengan gambar contoh isi berkas:

- CSV (*Comma-Separated Values*)
- TSV (*Tab-Separated Values*)
- XML (*eXtensible Markup Language*)
- JSON (*JavaScript Object Notation*)

**Gambar dan diagram**

1. **Contoh CSV.** Baris pertama adalah nama kolom: `treat,before,after,diff`. Tiap baris berikutnya satu pengamatan, nilainya dipisah koma. Sembilan baris terlihat, tiga kelompok perlakuan masing-masing tiga baris, dengan nilai (*before*, *after*, *diff*):
   - *No Treatment*: (13, 16, 3), (10, 18, 8), (16, 16, 0).
   - *Placebo*: (16, 13, −3), (14, 12, −2), (19, 12, −7).
   - *Seroxat (Paxil)*: (17, 15, −2), (14, 19, 5), (20, 14, −6).
   - Slide tidak menjelaskan arti kolomnya. Saya mengeceknya: pada kesembilan baris, `diff` sama dengan `after` dikurangi `before` (misalnya 16 − 13 = 3 dan 12 − 14 = −2). Jadi `treat` tampaknya jenis perlakuan (Seroxat/Paxil adalah nama dagang sebuah obat), `before` dan `after` adalah nilai sebelum dan sesudahnya, dan `diff` selisihnya. Kotak gambar terpotong, sehingga baris berikutnya tidak terlihat.
2. **Contoh TSV.** Sama dengan CSV, tetapi pemisahnya karakter tab. Tulisan `<TAB>` di slide mewakili tombol Tab. Kolomnya `Name`, `Age`, dan `Address`, dengan empat orang: Ryan (33, 1115 W Franklin), Paul (25, Big Farm Way), Jim (45, W Main St), dan Samantha (32, 28 George St).
3. **Contoh XML.** Baris pertama `<?xml version="1.0" encoding="UTF-8"?>` menyatakan versi dan pengodean huruf. Elemen akar `<bookstore>` memuat dua elemen `<book>`. Tiap `<book>` punya atribut `category` dan `cover`, serta elemen anak `<title lang="en">`, `<author>`, `<year>`, dan `<price>`. Dua bukunya: *Social Information Seeking* (2017, 62.58) dan *Hands-On Introduction to Data Science* (2019, 50.00), keduanya karya Chirag Shah, masing-masing berkategori “information science” (sampul keras) dan “data science” (sampul lunak).
4. **Contoh JSON.** Sebuah objek berkurung kurawal: `"empid": "SJ011MS"` dan `"personal"`, yang berisi objek bersarang dengan `"name": "Smith Jones"`, `"gender": "Male"`, `"age": 28` (angka tanpa tanda kutip), dan `"address"`, yang berisi `"streetaddress": "7 24th Street"`, `"city": "New York"`, `"state": "NY"`, dan `"postalcode": "10038"`. Gambar terpotong di kanan bawah.

**Istilah penting**

- **Format berkas**: aturan cara menyusun isi berkas agar dapat dibaca program.
- **CSV**: nilai dipisah koma; baris pertama biasanya nama kolom. Sederhana, ringkas, dan bisa dibuka di aplikasi lembar kerja. Kelemahannya: tidak menyimpan jenis data dan sulit menyatakan data bersarang.
- **TSV**: seperti CSV tetapi dengan pemisah tab. Berguna bila isi sel sering memuat koma, misalnya alamat.
- **XML**: bahasa penanda berbasis *tag* (label berkurung sudut). **Elemen** adalah pasangan *tag* pembuka dan penutup beserta isinya, **atribut** adalah keterangan tambahan di dalam *tag* pembuka (misalnya `category`), dan elemen boleh bersarang.
- **JSON**: format teks berisi objek berkurung kurawal dengan pasangan **kunci–nilai** (*key–value*). Sepengetahuan saya, JSON sangat umum sebagai bentuk data yang dikirim API web, termasuk API media sosial di slide 13.
- **Bersarang (*nested*)**: data di dalam data, seperti `address` di dalam `personal`.
- **Pemisah (*delimiter*)**: karakter pemisah antarnilai, yaitu koma atau tab.
- **UTF-8**: sistem pengodean huruf yang mencakup hampir semua aksara dunia.
- **Terstruktur dan semi terstruktur**: CSV dan TSV berbentuk tabel (terstruktur); XML dan JSON punya label dan hierarki tetapi tidak sekaku tabel (semi terstruktur). Lihat Bagian 2, slide 30.

**Contoh tambahan: satu data, empat format.** Orang yang sama (Ryan, umur 33) ditulis dalam keempat format.

CSV:

```
Name,Age
Ryan,33
```

TSV (`<TAB>` mewakili karakter tab):

```
Name<TAB>Age
Ryan<TAB>33
```

XML:

```
<person>
  <Name>Ryan</Name>
  <Age>33</Age>
</person>
```

JSON:

```
{
  "Name": "Ryan",
  "Age": 33
}
```

**Catatan.** Dua buku pada contoh XML adalah karya Chirag Shah, penulis rujukan pertama di slide 2. Tahun 2019 pada contoh itu tidak sama dengan tahun terbit 2020 di slide 2, jadi anggap isi contoh sebagai data ilustrasi, bukan katalog resmi.

**Mengapa penting.** Format menentukan seberapa mudah data dibaca oleh program dan manusia. Data tabel dari portal biasanya CSV; data dari API biasanya JSON; XML banyak dijumpai di dokumen dan sistem lama. Mengenali format adalah langkah pertama sebelum memuat data ke program analisis.

**Kaitan dengan slide sebelumnya.** Slide 13 menyebut data media sosial diambil lewat API; slide 14 menjelaskan wadah-wadah tempat data seperti itu biasa dikemas. Slide 15 menutup bab ini dengan tantangan yang muncul ketika data dikumpulkan.

**Contoh soal**

1. Pada contoh CSV, hitung nilai `diff` untuk baris “Seroxat (Paxil),14,19,?”. Cocokkah dengan slide?
   - **Pembahasan:** `diff` = `after` − `before` = 19 − 14 = 5. Cocok dengan nilai 5 di slide.
2. Format mana yang paling cocok untuk data bersarang beberapa lapis (orang, lalu alamat, lalu kota), dan mengapa CSV kurang cocok?
   - **Pembahasan:** JSON (atau XML), karena keduanya dapat menempatkan data di dalam data. CSV berbentuk tabel datar sehingga data bersarang harus diratakan.
3. Mengapa TSV kadang lebih aman daripada CSV untuk menyimpan alamat?
   - **Pembahasan:** alamat sering memuat koma, misalnya “Jl. Merdeka No. 5, Jakarta”. Pada CSV koma itu bisa dikira pemisah kolom kecuali teksnya diberi tanda kutip, sedangkan karakter tab jarang muncul di dalam teks.
